# StudyMaster 后端服务与监控看板

本服务为 **StudyMaster 微信小程序** 提供用户微信授权登录接入、数据埋点上报、运营监控大屏、
开屏公告下发与**上课提醒（微信订阅消息）**推送。

启动后可用页面：

| 页面 | 地址 | 作用 |
| --- | --- | --- |
| 📊 运营监控看板 | `/` 或 `/admin.html` | 用户、做题、激活码统计 |
| 📢 开屏公告 | `/announcement.html` | 改公告文案与配图，改完即生效 |
| ⏰ 上课提醒 | `/reminder.html` | 配订阅消息模板、作息时间，看订阅名单与下发日志 |

---

## 快速启动

### 1. 安装依赖与启动服务
在 `server` 目录下执行：
```bash
npm install
npm start
```
或者开发模式（支持热重载）：
```bash
npm run dev
```

启动后：
- 📡 API 服务地址：`http://localhost:3000`
- 📊 运营监控看板：`http://localhost:3000/admin.html`（或直接在浏览器访问 `http://localhost:3000`）

```env

WX_APPID=wx42669d80db35383f
```

- **开发/测试阶段**：若留空 `WX_APPSECRET`，后端会自动开启 **Mock 模式**，可在微信开发者工具中直接点击授权登录进行全流程调试。
- **正式上线**：登录 [微信公众平台](https://mp.weixin.qq.com/)，在「开发管理 -> 开发设置」中获取 `AppSecret` 填入 `.env`，服务将通过微信官方 `jscode2session` 接口校验真实 `openid`。

## 开屏公告管理（改内容不用重新发版）

小程序启动时弹出的公告，内容全部由本服务下发。运营改文案、换配图只需在网页后台操作，
**保存后用户下次打开小程序即生效，不需要重新提交审核、也不需要发新版本**。

### 打开后台

| 环境 | 地址 |
| --- | --- |
| 本地 | `http://localhost:3000/announcement.html` |
| 线上（云托管） | `https://studymaster-299598-11-1471610879.sh.run.tcloudbase.com/announcement.html` |

也可以从运营看板 `admin.html` 右上角的 **「📢 开屏公告」** 按钮进入。

首次打开需要填写**管理口令**（`ADMIN_TOKEN`），点「记住口令」后浏览器会保存，下次不用再输。
默认口令是 `studymaster_admin_2026`，**正式环境请在 `.env` 里改成自己的复杂字符串**并重新部署：

```env
ADMIN_TOKEN=你的复杂口令
```

### 可配置项

| --- | --- |
| 开关与弹出策略 | 总开关、每次打开都弹 / 同一条只弹一次、公告版本号、弹出延迟、点遮罩是否可关闭 |
| 标题与正文 | 标题、正文（支持换行） |

页面右侧有**实时手机预览**，改什么立刻能看到排版效果。

### 图片为什么不直接用 URL

微信规定 `<image>` 组件加载**网络图片**时，域名必须加进小程序的「服务器域名 → downloadFile 合法域名」，
否则**真机上显示不出来**（开发者工具勾选"不校验合法域名"对真机无效，这是最常见的踩坑点）。

因此后台上传的图片**不走图片 URL**，而是由接口以 base64 随配置一起下发，小程序落地成本地文件后直接使用。
这样无论换多少次图，都**不需要动域名白名单**。接口还带版本号（`imageVersion`），图片没变时不会重复传输，不浪费流量。

> 若确实要填外部图片地址，请把该域名加进「downloadFile 合法域名」，或优先使用「上传新图」。

### 接口清单

| 方法 | 路径 | 说明 | 鉴权 |
| --- | --- | --- | --- |
| GET | `/api/announcement` | 小程序拉取公告（可带 `?imgVersion=` 避免重复下发图片、`?withImage=0` 只取文字） | 公开 |
| GET | `/api/announcement/admin` | 后台读取完整配置 | 需 `x-admin-token` |
| PUT | `/api/announcement` | 保存公告配置 | 需 `x-admin-token` |
| POST | `/api/announcement/image` | 上传配图（`{ dataUrl, fileName }`，base64） | 需 `x-admin-token` |

### ⚠️ 数据持久化提醒

公告配置存在 `data/studymaster.json`，配图存在 `data/uploads/announcement/`。
微信云托管的容器文件系统是**临时的**，容器重启后这两个位置的数据会丢失（学生数据同理）。
建议在云托管控制台给容器**挂载一个持久化存储卷到 `/app/data`**，一次性解决。

配图文件万一丢失，接口会自动回退到小程序包内的默认图片，不会出现空白图。

### 修改后如何生效

- **只改文案 / 换图**：后台点保存即可，用户下次打开小程序就能看到，**无需任何部署或审核**。
- **改了后端代码本身**（比如新增字段）：需要重新部署一次容器，此后日常改内容仍然不用再部署。

### 部署到云托管（含公告功能时必须做一次）

小程序端走两条通道，**决定了你能在哪里看到改动**：

| 运行环境 | 请求通道 | 说明 |
| --- | --- | --- |
| 开发者工具模拟器 | 直连 `http://localhost:3000` | 本机 `node server.js` 起着就能看到最新内容（`project.private.config.json` 已关掉域名校验） |
| 真机 / 真机调试 / 正式用户 | `wx.cloud.callContainer` → 云托管 | **云托管没部署新版本时接口 404，小程序会静默回退到包内兜底图，看起来「改了没反应」** |

部署步骤：

1. 在项目根目录把 `server` 打成 zip（与仓库里 `server.zip` 同格式：`server` 目录内容放在 zip 根，含 `Dockerfile`）。
2. **不要把 `data/` 打进包** —— 本机那份数据库与线上是两份不同数据（线上有真实用户与激活码），带上去会用本机数据覆盖线上。
   `data/` 和 `data/uploads/` 都会在启动时自动创建，空目录起来即可。
3. 云托管控制台 → 服务 `studymaster`（环境 `prod-d0g39zvr13ada49af`）→ 新建版本 → 上传 zip → 全量发布。
4. 若容器**没有**挂持久化卷，重新部署会清空容器内的 `data/`：部署前先用后台导出用户/激活码留档，或先挂卷到 `/app/data`。
5. 部署完打开 `https://<云托管域名>/announcement.html`，用管理口令保存一次公告内容（新容器里初始是内置默认值）。

排查「后台改完小程序没变化」：看开发者工具 Console，小程序端会打印
`[Announcement] 已加载后端公告配置…` 或 `[Announcement] 远端配置拉取失败…（含原因）`，据此判断是没部署还是走了兜底。

## 上课提醒（微信订阅消息）

学生在课表页点「上课提醒」授权后，**每节课前 N 分钟**由本服务调用微信
`subscribeMessage.send` 把课程、时间、教室推送到用户的微信「服务通知」。

### 一次性配置（只做一次）

1. **微信公众平台** → 功能 → 订阅消息 → 公共模板库 → 搜索「上课提醒 / 课程提醒」→ 选用并添加。
   - 教育类目一般能拿到**长期订阅**模板（一次授权长期有效）；
   - 若只有**一次性订阅**模板，则每次授权只能下发一条，需要学生反复补充次数。
2. 打开后台 `https://<云托管域名>/reminder.html`（或从 `admin.html` 右上角「⏰ 上课提醒」进入）。
3. 点 **「读取微信模板」** → 在列表里点 **「选用」** —— 模板 ID、模板类型、字段映射会自动填好。
4. 点 **「保存配置」**。之后在小程序真机上点一次「上课提醒」即可。

> 💡 **本小程序实测结果（AppID `wx83e4351eecff8a27`）**
> 服务类目为「企业管理 / 教育信息展示 / 公关·推广·市场调查」，
> 公共模板库里正好有一个 **「上课提醒」** 模板（tid=`77439`，类目=教育信息展示），
> 字段是 **上课地点 / 上课时间 / 授课教师 / 课程名称** —— 和课表数据完全对得上。
> 但它是 **一次性订阅**（type=2）：**每授权一次只能发一条**，
> 所以小程序端专门做了「+1 次」按钮，学生点几次就有几次提醒额度。
> 想改成长效，需要把小程序类目补充成能申请长期订阅的教育类目后再看模板库。
>
> 在后台上点「🔍 搜索公共模板库」也能看到这些信息（只读查询，不会改动账号）。

> ⚠️ **字段不能多传**：模板里没有声明的字段下发过去，微信会直接报 `47003`。
> 「选用」模板时会把该模板声明的字段记下来，后端只下发这些字段。
> 如果你是手工粘贴模板 ID，请务必也点一次「读取微信模板 → 选用」，或手动把字段填对。

### 后台可配置项

| 区域 | 内容 |
| --- | --- |
| 模板 | 模板 ID、模板类型（长期 / 一次性）、下发环境（正式版 / 体验版 / 开发版）、点击跳转页面 |
| 字段映射 | 课程名称 / 上课时间 / 上课地点 / 授课老师 / 备注 分别对应模板里的哪个字段 |
| 时间格式 | 「上课时间」发完整时段（`14:00~15:40`）还是只发开始时间（`14:00`）—— 微信「上课提醒」模板的示例就是时段格式 |
| 备注文案 | 支持 `{course}` `{location}` `{time}` `{period}` `{teacher}` `{ahead}` 占位符，最多 20 字 |
| 校历 | 学期开始日期（第 1 周周一）、学期总周数 |
| 作息时间 | 每个大节的上下课时间 —— **必须与课表页显示的作息一致**，否则提醒时刻会偏 |
| 限流 | 每人每天最多发几条（默认 8，防配置错误刷屏） |
| 调试 | 立即扫描一轮 / 预演（只算不发）/ 给指定 openid 发测试消息 |

### 定时扫描怎么跑

服务端每 **30 秒**扫一轮，判断「现在是否落在某节课的提醒窗口内（`开始时间 - 提前量` 到 `开始时间`）」。
同一位学生的同一节课**只发一次**（以 `openid + 课程开始时刻 + 模板 ID` 为指纹，成功失败都落日志），
容器重启或临时扩多实例都不会重复轰炸。

两种触发方式，任选其一（也可以都开）：

| 方式 | 说明 |
| --- | --- |
| 容器内定时器（默认开） | 云托管控制台把**最小实例数设为 1**，否则缩容到 0 时定时器不跑 |
| 外部定时任务 | 让云函数 / 任意 cron 服务每分钟请求 `GET https://<域名>/api/reminder/cron?token=<ADMIN_TOKEN>` |

关掉容器内定时器：环境变量 `ENABLE_REMINDER_SCHEDULER=0`。

### 时区（很重要）

云托管容器默认 `TZ=UTC`，直接 `new Date()` 算「今天第几节课」会整体偏 8 小时。
本服务的所有日期计算都按 `TZ_OFFSET_MINUTES`（默认 `480` = 北京时间）自行换算，
**不依赖容器本地时区**；`Dockerfile` 里也顺手设了 `TZ=Asia/Shanghai` 双保险。

### 常见错误码

| errcode | 含义 / 处理 |
| --- | --- |
| 43101 | 用户拒绝接收该消息 → 需要重新引导授权（一次性模板额度用尽也是这个码） |
| 40037 | 模板 ID 无效 → 后台重新读取模板并选用 |
| 47003 | 模板参数不满足格式要求 → 多半是字段对不上或超长，点「读取微信模板 → 选用」重配 |
| 41030 | `page` 路径不正确 → 检查「点击跳转页面」 |
| 45009 / 45011 | 接口调用频率超限 → 调大提前量或减少订阅人数 |

日志里这些码会被自动翻译成人话，直接看后台「最近下发日志」的「说明」列即可。

### 数据持久化

提醒配置、订阅名单、下发日志都存在 `data/studymaster.json`。
和公告一样，**强烈建议给云托管容器挂持久化卷到 `/app/data`**，否则重新部署会清空订阅关系
（用户需要重新授权一次才能恢复提醒）。
